## 1. 背景

学校原来的教务系统老旧。实验课集中开课时，学生要提交危化品领用，老师要查库存，
几拨人同时操作，并发一高系统就扛不住。危化品领用与台账因此从教务系统里拆出来，
单独做成一个服务。

拆出来不只是为了分流并发。这条链路的账要能自证：安全检查要回答谁在何时领了哪瓶、
出自哪个批次、谁批准；账和实物对不上时，要能定位到具体哪一笔。教务系统的主线是排课
与成绩，不承载这类强追溯的库存单据。

## 2. 解决什么问题

两条业务主线，一个收口：

| 主线 | 链路 | 回答的问题 |
|---|---|---|
| 一 | 领用申请 → 双人审批 → FEFO 出库 → 台账 | 一笔领用怎么走完？并发下怎么不超发、不重复批？ |
| 二 | 盘点 → 实盘录入 → 确认调账 → 对账 | 账实不符怎么发现、怎么调、怎么证明调后是对的？ |

主线一保证每一笔都算对；主线二负责发现有没有漏记的动作。两条都落在只增不改的台账上，
任一时刻的批次余额都能由最后一笔流水复现。

旁路功能：MSDS 检索与带引用的问答、禁忌混放检查、报废申请审批、运维巡检告警。
旁路失败不影响开单与出库。

## 3. 给谁用

| 角色 | 主要操作 |
|---|---|
| 学生 / 实验员 | 提交领用，查看自己的申请与试剂安全摘要 |
| 审批人 | 审批领用与报废；高危试剂需要两人各批一次 |
| 库管 / 管理员 | 建档、入库、出库、核销、盘点、报废、账号与索引管理 |

## 4. 做到什么程度

已实现：

- 两条主线完整闭环，含高危试剂双人复核、部分出库、批次级与汇总级对账。
- 并发正确性靠数据库条件更新与乐观锁，不依赖应用层锁；单号用数据库号段，
  多实例重建 MSDS 索引用数据库行锁。
- MSDS 检索、带引用问答、禁忌混放检查、报废审批、运维告警均已接入。
- 前端是随 jar 发布的静态 Vue3 页面，登录、领用、盘点、报废、检索与告警都可操作。
- 273 个测试，默认套件不需要任何中间件。

边界（被问到主动说明）：

- 单体部署。压测在本机 MySQL 容器上做 10 秒单场景，数字只说明链路的相对变化，
  不是生产容量。
- 多实例一致性只做到单号号段与索引行锁，没有做跨实例长稳。
- 演示种子是 18 种试剂、18 份 MSDS、51 对禁配规则，不是完整 GB 15603；
  「检查通过」只说明已知规则里没有冲突。
- 没有邮件、短信、webhook 通知通道，告警只在应用内表和接口里可见。

## 5. 技术结构

| 层 | 选型 |
|---|---|
| 运行时 | Spring Boot 3.5 · Java 21 |
| 存储 | 默认 H2；`mysql` profile 连 MySQL 8.4；Flyway V1–V17 |
| 数据访问 | JPA 为主；只读报表用 MyBatis-Plus |
| 可选组件 | Redis（只缓存试剂档案）、RabbitMQ（MSDS 编码任务）、PostgreSQL + pgvector（向量检索） |
| 鉴权 | Spring Security + JWT，USER / APPROVER / ADMIN 三角色 |
| 前端 | 静态 Vue3，无 Node 构建链 |
